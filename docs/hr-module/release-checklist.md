# Релиз модуля «Приём на работу»: чек-лист

Для оператора релиза и администратора сервера. Ветка `feature/hr-hiring`.

## До релиза

- [ ] **Чистая рабочая копия прода.** В `/home/admaza/projects/du` лежит неотслеживаемая папка
      `docs/hr-module/` (входные материалы ОУП). Эти же файлы есть в ветке. Удалить её на проде
      **до** релиза: иначе проверка «DIRTY PROD» остановит деплой, а git откажется перезаписать
      неотслеживаемые файлы при слиянии. Файлы вернутся из git вместе с релизом:
      `rm -r /home/admaza/projects/du/docs/hr-module`
- [ ] **LibreOffice и шрифты** (нужен sudo, делает администратор сервера):
      `sudo apt install --no-install-recommends libreoffice-writer fonts-liberation`
      Проверка: `soffice --version`; от пользователя веб-сервера:
      `sudo -u www-data soffice --headless --version`.
- [ ] **`.env` прода:** `HR_LIBREOFFICE_BINARY=/usr/bin/soffice` (путь из `command -v soffice`),
      при необходимости `HR_LIBREOFFICE_TIMEOUT=60`, `HR_PREVIEW_TTL_HOURS=24`.
      Без `HR_LIBREOFFICE_BINARY` модуль работает, предпросмотр пишет «недоступен».

## Релиз

- [ ] Слить `feature/hr-hiring` → `dev` → `./scripts/deploy/deploy.sh release` (по команде владельца).
- [ ] Миграции (5 шт., `2026_10_22_000001…000005`): таблицы `hr_*`, падежные формы в `org_units` и
      `positions`, сид — русские формы подразделений по правилам, должности АУП/УВП, реквизиты
      работодателя из образца договора (`app_settings.hr_employer`). Новых composer-пакетов нет.
- [ ] Сборка фронтенда (`npm run build`) — как обычно в релизе.
- [ ] Очередь: предпросмотр PDF идёт через обычный worker (таймаут задачи 100 с, LibreOffice — 60 с).
- [ ] Планировщик: `hr:prune-previews` раз в час (старые PDF-предпросмотры), `hr:purge-deleted`
      ежедневно в 03:30 (окончательно удаляет черновики, удалённые больше 30 дней назад).

## После релиза

- [ ] **Роли:** «Пользователи» → назначить роль «Отдел кадров» сотрудникам ОУП.
- [ ] **Права** («Отдел кадров» → «Приём на работу» → «Настройки» → «Права», только администратор):
      - «Сканы документов и социальный статус» — кому положено (например, начальнику ОУП);
      - «Пополнение справочника и подтверждение падежных форм» — кто ведёт справочник.
- [ ] **Настройки работодателя** — проверить реквизиты, подписанта, визу, перерыв по умолчанию.
- [ ] **Проверка ОУП** (юристы / ОУП):
      - казахские тексты, которых нет в образце, — в `app/Services/Hr/HiringTexts.php` (помечены
        «проверить в ОУП»): п. 1.7 при совместительстве, п. 3.1.2 при графике АУП, п. 3.1 при сменном
        графике, п. 2.1 для бессрочного договора и замещения, окончание договора при замещении,
        формулировки приказа (срок, испытание, вид работы);
      - шаблон приказа (`resources/hr/templates/order.docx`) — черновой, образца ОУП не было;
      - падежные формы справочника: «Настройки» → «Справочник» → «Только непроверенные».
- [ ] **Бэкап:** `APP_KEY` хранится в `env_*.backup` резервной копии прода — ИИН и № удостоверения
      без него не расшифровать. Файлы модуля — в `storage/app/private/hr` (входят в архив `storage`).
- [ ] **prod → dev:** `prod_to_dev_sync.sh` теперь вызывает `purge_dev_hr_data.sh` и очищает
      HR-таблицы и файлы в dev после копирования.
