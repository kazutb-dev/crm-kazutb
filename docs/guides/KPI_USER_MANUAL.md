## 1. Общее описание

Система KPI (Key Performance Indicators — Ключевые показатели эффективности) предназначена для оценки профессиональной деятельности сотрудников университета. Каждый сотрудник заполняет показатели своей деятельности, которые последовательно проверяются руководителями нескольких уровней.

**Основной процесс:**
1. Сотрудник создаёт и подаёт записи по своим показателям
2. Заведующий кафедрой проверяет и одобряет записи
3. Декан факультета утверждает записи
4. Структурное подразделение выносит финальное решение

---

## 2. Роли пользователей

В системе предусмотрено пять ролей. Роль определяет, какие страницы доступны и какие действия разрешены.

| Роль | Обозначение | Кто это |
|------|-------------|---------|
| **Преподаватель** | `teacher` | Штатный преподаватель, научный сотрудник |
| **Заведующий кафедрой** | `hod` | Руководитель кафедры |
| **Декан** | `dean` | Декан факультета |
| **Структурное подразделение** | `structural` / `department` | Сотрудник административного/структурного подразделения |
| **Администратор** | `admin` | Системный администратор, полный доступ |

> Роль назначается системным администратором и отображается в профиле пользователя.

## 3. Этапы работы с KPI

Работа с KPI ведётся в рамках **KPI-периода** (учебный год / семестр). Период делится на три стадии:

### Стадия 1 — Планирование (`STAGE_PLAN`)
- Вводятся плановые (целевые) значения показателей
- Сотрудник указывает, сколько единиц планирует выполнить

### Стадия 2 — Факт (`STAGE_FACT`)
- Основная рабочая стадия
- Сотрудники заполняют фактически достигнутые значения
- Прикладываются подтверждающие документы
- Записи проходят проверку по иерархии

### Стадия 3 — Проверка (`STAGE_REVIEW`)
- Административное подведение итогов
- Финальная проверка и утверждение

> Текущую стадию активного периода устанавливает администратор в разделе **«Настройки KPI»**.

## 4. Статусы записей

Каждая запись KPI в процессе обработки проходит следующие статусы:

```
[Черновик] → [Подана] → [На проверке деканом] → [На проверке структуры] → [Утверждена]
                ↓                  ↓
           [Возвращена]      [Возвращена]
                ↓
         (автор исправляет и подаёт снова)
                                              → [Отклонена] (структурой)
                                              → [Заблокирована] (системой)
```

| Статус | Значение | Кто действует |
|--------|----------|---------------|
| `draft` — **Черновик** | Запись создана, но ещё не подана | Автор |
| `submitted` — **Подана** | Ожидает проверки заведующим кафедрой | Заведующий кафедрой |
| `returned` — **Возвращена** | Возвращена автору на доработку | Автор |
| `pending_dean` — **На проверке деканом** | Одобрена заведующим, ожидает декана | Декан |
| `pending_structural` — **На проверке структуры** | Одобрена деканом, финальная проверка | Структурное подразделение |
| `approved` — **Утверждена** ✅ | Финально одобрена, баллы зачтены | — |
| `rejected` — **Отклонена** ❌ | Отклонена структурным подразделением | — |
| `locked` — **Заблокирована** 🔒 | Заблокирована системой | — |

> **Важно:** Запись можно редактировать только в статусах `draft` и `returned`. После подачи редактирование недоступно до возврата.

## 5. Иерархия проверки

Проверка проходит **три уровня**. Каждый уровень может одобрить (передать на следующий уровень) или вернуть запись автору.

```
┌─────────────────────────────────────────────────────────────────┐
│                      АВТОР (Преподаватель / ЗКаф / Декан)       │
│         Создаёт → заполняет → прикладывает файлы → подаёт       │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│              УРОВЕНЬ 1: Заведующий кафедрой (HOD)               │
│  Очередь: «KPI — Проверка Кафедрой»                             │
│  Действия: ✅ Одобрить → «pending_dean»                          │
│            ↩ Вернуть  → «returned» (автор исправляет)           │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│                    УРОВЕНЬ 2: Декан (Dean)                       │
│  Очередь: «KPI — Проверка Деканом»                              │
│  Действия: ✅ Одобрить → «pending_structural»                    │
│            ↩ Вернуть  → «returned» (автор исправляет)           │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│            УРОВЕНЬ 3: Структурное подразделение                  │
│  Очередь: «KPI — Проверка Структурой»                           │
│  Действия: ✅ Утвердить → «approved» (баллы зачтены)            │
│            ❌ Отклонить → «rejected» (без возврата)              │
└─────────────────────────────────────────────────────────────────┘
```

### Кто может проверять кого

| Проверяющий | Видит записи | Может действовать |
|-------------|--------------|-------------------|
| Заведующий кафедрой | Записи преподавателей **своей кафедры** со статусом `submitted` | Одобрить / Вернуть |
| Декан | Записи **своего факультета** со статусом `pending_dean` | Одобрить / Вернуть |
| Структурное подразделение | Записи **закреплённых за ним подразделений** со статусом `pending_structural` | Утвердить / Отклонить |
| Администратор | **Все** записи любого статуса | Любые действия |

> Заведующий кафедрой и декан **также являются сотрудниками** и могут создавать собственные KPI-записи. Их записи проверяются на уровне вышестоящего руководства (декан / структура).

## 6. Инструкция по ролям

### 6.1 Преподаватель

#### Доступные страницы
- **KPI — Мои показатели** (`/kpi/my-form`) — основная рабочая страница
- **KPI — Сводка** (`/kpi/summary`) — просмотр своих итогов

#### Пошаговая инструкция

**Шаг 1. Открыть форму**
Перейти в меню: **KPI → KPI — Мои показатели**.

**Шаг 2. Создать запись**
1. Нажать кнопку **«Добавить запись»** (или **«+»**)
2. Выбрать показатель из списка (например, «Количество читаемых лекций»)
3. Ввести **плановое значение** (план) и/или **фактическое значение** (факт)
4. Если показатель требует файл — прикрепить подтверждающий документ
5. Нажать **«Сохранить»** — запись сохраняется в статусе `draft` (черновик)

**Шаг 3. Проверить и подать**
1. Убедиться, что все данные заполнены корректно
2. Нажать **«Подать»** / **«Submit»**
3. Статус изменится на `submitted` — запись ушла на проверку заведующему

**Шаг 4. Ожидать проверки**
- Отслеживать статус на странице «Мои показатели»
- Если запись **возвращена** (`returned`): прочитать комментарий проверяющего, исправить данные и подать повторно
- Если запись **утверждена** (`approved`): баллы зачтены ✅

#### Что нельзя делать
- Редактировать поданную запись (только если она возвращена)
- Удалять утверждённые записи
- Просматривать записи других сотрудников

---

### 6.2 Заведующий кафедрой (HOD)

#### Доступные страницы
- **KPI — Мои показатели** — собственные записи (как преподаватель)
- **KPI — Проверка Кафедрой** (`/kpi/review-queue`) — очередь проверки
- **KPI — Сводка** — сводный отчёт по кафедре

#### Работа с очередью проверки

**Страница «Проверка Кафедрой»** показывает все поданные записи (`submitted`) преподавателей вашей кафедры.

**Как проверить запись:**
1. Перейти в **KPI → Проверка Кафедрой**
2. В таблице найти нужную запись (фильтр по преподавателю, показателю, дате)
3. Нажать на запись или кнопку **«Просмотр»** для детального изучения
4. Проверить: правильность показателя, значение, прикреплённые файлы
5. Принять решение:
   - **«Одобрить»** — запись уходит деканупри статусе `pending_dean`
   - **«Вернуть»** — запись возвращается преподавателю, обязательно указать **причину** в комментарии

#### Массовые действия
- Возможен выбор нескольких записей и одобрение/возврат группой

#### Собственные записи
Заведующий кафедрой также заполняет **собственные KPI-записи** (как обычный преподаватель). Его записи проверяет декан.

---

### 6.3 Декан

#### Доступные страницы
- **KPI — Мои показатели** — собственные записи
- **KPI — Проверка Деканом** (`/kpi/approval-queue`) — очередь утверждения
- **KPI — Сводка** — сводный отчёт по факультету

#### Работа с очередью утверждения

**Страница «Проверка Деканом»** показывает записи со статусом `pending_dean` — то есть уже проверенные заведующими кафедр.

**Как утвердить запись:**
1. Перейти в **KPI → Проверка Деканом**
2. Выбрать запись для просмотра
3. Принять решение:
   - **«Одобрить»** — статус становится `pending_structural`, запись уходит в структурное подразделение
   - **«Вернуть»** — статус становится `returned`, запись возвращается автору с комментарием

> Декан видит записи **всех кафедр своего факультета**. Если кафедра не относится к факультету декана — запись не будет видна.

#### Собственные записи декана
Декан также создаёт собственные KPI-записи. Их итоговое утверждение выполняет структурное подразделение (минуя уровень декана).

---

### 6.4 Структурное подразделение

#### Доступные страницы
- **KPI — Проверка Структурой** (`/kpi/structural-queue`) — финальная очередь
- **KPI — Сводка** — обзор по закреплённым подразделениям

#### Работа с финальной очередью

**Страница «Проверка Структурой»** показывает записи со статусом `pending_structural` по **подразделениям, закреплённым за данным пользователем**.

**Как вынести финальное решение:**
1. Перейти в **KPI → Проверка Структурой**
2. Изучить запись: показатель, значение, файлы, историю проверок
3. Принять решение:
   - **«Утвердить»** ✅ — статус `approved`, баллы зачтены, запись закрыта
   - **«Отклонить»** ❌ — статус `rejected`, запись закрыта без зачёта баллов

> **Важно:** Структурное подразделение **не может вернуть** запись автору — только утвердить или отклонить. При сомнениях рекомендуется связаться с деканом/заведующим кафедрой до принятия решения.

#### Что видит структурное подразделение
- Только записи подразделений, **явно закреплённых** за данным пользователем в настройках системы
- Записи других структурных подразделений не видны

### 6.5 Администратор

Администратор имеет полный доступ ко всем функциям KPI.

#### Эксклюзивные страницы
| Страница | Адрес | Назначение |
|----------|-------|------------|
| Настройки KPI | `/kpi/settings` | Управление периодами, стадиями, правами доступа |
| Показатели | `/kpi/indicators` | Создание/редактирование KPI-показателей |
| Подразделения | `/kpi/divisions` | Просмотр KPI по подразделениям |
| Структурные единицы | `/kpi/structural-units` | Управление структурными подразделениями |

#### Управление периодами
1. Перейти в **Настройки KPI → Периоды**
2. Создать новый период (учебный год/семестр)
3. Установить текущую стадию: `Планирование` / `Факт` / `Проверка`
4. Открыть/закрыть период для редактирования

#### Управление правами доступа (Access Grants)
Администратор выдаёт специальные права:
| Право | Что даёт |
|-------|----------|
| `kpi_admin` | Полный доступ к KPI, обход политик |
| `review_queue` | Доступ к очереди проверки (кафедра) |
| `approval_queue` | Доступ к очереди утверждения (декан) |
| `structural_queue` | Доступ к структурной очереди |
| `indicators` | Управление показателями |
| `analytics` | Аналитика KPI |
| `periods` | Управление периодами |

#### Действия администратора с записями
- Просматривать и редактировать **любые** записи
- Одобрять/возвращать/отклонять записи **любого статуса**
- Пересчитывать баллы

## 7. Разделы KPI (показатели)

Все KPI-показатели разделены на **5 разделов**:

| Код раздела | Полное название | Описание |
|-------------|-----------------|----------|
| `teaching` | **УМР** — Учебно-методическая работа | Лекции, практики, учебные материалы |
| `science` | **НИР** — Научно-исследовательская работа | Публикации, гранты, патенты |
| `social` | **СВР** — Социально-воспитательная работа | Кураторство, мероприятия |
| `qualification` | **УПК** — Учебно-профессиональная квалификация | Повышение квалификации, сертификаты |
| `survey` | **К5** — Анкетирование | Оценка студентами |

Каждый показатель имеет:
- **Единицу измерения** (часов, статей, мероприятий и т.д.)
- **Базовые баллы** за единицу
- **Тип расчёта**: ручной / автоматический / по формуле
- **Требование файла**: да / нет

## 8. Начисление баллов

### Типы расчёта баллов

| Тип | Описание |
|-----|----------|
| `manual` | Баллы вводятся вручную или устанавливаются администратором |
| `auto` | Баллы = базовые_баллы × фактическое_значение |
| `formula` | Баллы рассчитываются по сложной формуле (scoring_rules) |

### Нормативные баллы (НПУ)

| Должность / Роль | Плановые баллы |
|-----------------|----------------|
| Профессор | 1000 баллов |
| Доцент | 800 баллов |
| Старший преподаватель | 600 баллов |
| Преподаватель | 500 баллов |
| Заведующий кафедрой | 500 баллов (200 для кафедр ГиИЯ, СГД, ФВ) |
| Декан | 2000 баллов |

### Когда баллы зачитываются
Баллы считаются **зачтёнными** только после получения статуса `approved`. Записи в промежуточных статусах в итоговый расчёт не включаются.

## 9. Страницы системы

### KPI — Мои показатели (`/kpi/my-form`)
Персональная форма заполнения KPI. Доступна преподавателям, заведующим кафедрами и деканам.

- Отображает записи по разделам (УМР, НИР, СВР, УПК, К5)
- Показывает суммарные набранные баллы
- Позволяет создавать, редактировать и подавать записи

### KPI — Сводка (`/kpi/summary`)
Обзорная страница с агрегированными данными. Вид зависит от роли:
- **Преподаватель**: собственные итоги
- **Заведующий кафедрой**: итоги по кафедре с разбивкой по сотрудникам
- **Декан**: итоги по факультету с разбивкой по кафедрам
- **Структурное подразделение**: итоги по закреплённым подразделениям (вкладки «Факультеты» и «Ожидают»)

### KPI — Проверка Кафедрой (`/kpi/review-queue`)
Очередь для заведующих кафедрами. Показывает записи со статусом `submitted` своей кафедры.

### KPI — Проверка Деканом (`/kpi/approval-queue`)
Очередь для деканов. Показывает записи со статусом `pending_dean` своего факультета.

### KPI — Проверка Структурой (`/kpi/structural-queue`)
Финальная очередь. Показывает записи со статусом `pending_structural` закреплённых подразделений.

### Детальный просмотр записи (`/kpi/entries/{id}`)
Полная информация о записи:
- Все поля и значения
- Прикреплённые файлы
- **История изменений статуса** (кто и когда изменил, комментарий)

## 10. Часто задаваемые вопросы

**Q: Я подал запись, но хочу её изменить. Как?**
A: Самостоятельно изменить поданную запись нельзя. Обратитесь к заведующему кафедрой с просьбой вернуть запись. После возврата (статус `returned`) запись снова станет редактируемой.

**Q: Заведующий кафедрой вернул мою запись. Что делать?**
A: Откройте запись, прочитайте комментарий проверяющего, внесите исправления и нажмите «Подать» повторно.

**Q: Почему я не вижу записи своих подчинённых в очереди проверки?**
A: Проверьте, что у вас есть право `review_queue` (для заведующих) или `approval_queue` (для деканов). Обратитесь к администратору для выдачи прав. Также убедитесь, что сотрудники действительно подали записи (статус `submitted`).

**Q: Структурное подразделение отклонило запись. Можно ли её восстановить?**
A: Самостоятельно — нет. Обратитесь к администратору системы. Администратор может изменить статус записи.

**Q: Когда можно создавать и подавать записи?**
A: Только в **активном периоде** на стадии **«Факт»** (`STAGE_FACT`). Если период закрыт или идёт другая стадия — форма будет недоступна.

**Q: Нужно ли прикладывать файлы к каждой записи?**
A: Зависит от показателя. Если в настройках показателя включено **«Требуется файл»** — файл обязателен. Без него система не позволит подать запись.

**Q: Я — заведующий кафедрой. Кто проверяет мои собственные записи?**
A: Ваши записи пропускают уровень кафедры и отправляются напрямую декану факультета.

**Q: Я — декан. Кто проверяет мои записи?**
A: Ваши записи проверяет структурное подразделение (без уровня декана).

**Q: Можно ли видеть историю изменений записи?**
A: Да. Откройте детальный просмотр записи (`/kpi/entries/{id}`) — там отображается полная история статусов с указанием исполнителя, даты и комментария.

**Q: Что означает статус «Заблокирована» (locked)?**
A: Запись заблокирована системой (например, после закрытия периода). Никакие действия с ней невозможны.
