# Contributing to CRM KazUTB

## Workflow
- Все изменения — через feature-ветки (feature/your-feature)
- Мержить только через Pull Request (PR)
- Каждый PR — с описанием задачи и ссылкой на issue (если есть)
- После мержей — обновлять README.md, если меняются правила или структура

## Стиль коммитов
- feat: новая функциональность
- fix: исправление бага
- chore: технические задачи, обновления зависимостей
- docs: изменения в документации
- refactor: рефакторинг

## Проверки
- Перед PR — убедись, что проходят все тесты (phpunit, eslint и др)
- Линтеры обязательны (php-cs-fixer, pint, eslint, prettier)

## Политика
- "Если код не в GitHub — его не существует"
- Не держи код локально дольше 1-2 дней
- Вопросы — через Issues, тегай @aulykpan
